## Background

`puppetlabs-sce_linux` is adding CIS Amazon Linux 2023 (epic CEM-5007). `abide sce generate
reference` and the coverage tooling look up OS facts through
`AbideDevUtils::Ppt::FacterUtils::FactSets#find_by_fact_value_tuples` using `os.name` /
`os.release.major`. For `Amazon` / `2023` this returns `nil`, causing:

```
AbideDevUtils::Errors::BenchmarkLoadError: Error loading benchmark: undefined method `[]' for nil:NilClass, Framework: cis, OS Name: Amazon, OS Version: 2023
```

`abide_dev_utils` pins `facterdb ~> 4.1.0`, which has no `amazon-2023` fact files, and
`files/fact_sets/` has none either.

### Why not bump `facterdb`

`facterdb` 4.5.0 ships `amazon-2023-x86_64.facts`, but only under the OpenFact `5.1`, `5.2`, `5.4`
and `5.6` directories; the `facterdb` maintainers now generate facts with OpenVox. That is enough
for `FactSets` (which keys fact sets by directory and ignores `facterversion`), but not for
`rspec-puppet-facts`:

- `rspec-puppet-facts` does not ask the installed Facter for its version. It maps the Puppet gem
  version to a Facter version via `ext/puppet_agent_facter_versions.json`, which is now built from
  OpenVox agent releases. Perforce Puppet 8.22.0 maps to the nearest lower entry, OpenVox 8.19.2 →
  Facter **4.11.0**; Puppet 9.1.0 maps to OpenVox 9.0.0-rc2 → OpenFact **6.2.0**.
- It then selects facts with `~> <ver>.0`, falling back to `< <major>.<minor+1>`. On Puppet 8 that
  means `facterversion < 4.12`, so OpenFact 5.x factsets are never chosen and the OS is silently
  dropped from `on_supported_os`.
- Confirmed in `sce_linux` CI (`main`, run 38534825592): the Puppet 8 / Ruby 3.2 RSpec job has zero
  `redhat-10` or `oraclelinux-10` contexts; the Puppet 9 / Ruby 4.0 job covers them via OpenFact 5.x
  fallback.

Bumping `facterdb` would also force `required_ruby_version >= 3.2.0` (a `facterdb` 4.5 requirement)
and would not be adopted by `sce_windows`, which pins `facterdb <= 4.1.0`.

Instead, we vendor the upstream AL2023 facts into `files/fact_sets/`, relabeled as Facter 4.11.0,
where we control them. We also relabel the existing `redhat-10` factset (currently `5.1.0`) to
`4.11.0` so all EL10-era local factsets are selectable by Puppet 8 once `sce_linux` points
`FACTERDB_SEARCH_PATHS` at this directory (tracked separately — `FactSets` passes the path to
`FacterDB.external_fact_files` directly and does not expose it to `FacterDB.get_facts`).

## Change

**File:** `files/fact_sets/amazon-2023-x86_64.facts` (new)

Copy `facts/5.6/amazon-2023-x86_64.facts` from `facterdb` 4.5.0 (real AL2023 host data, not cloned
from a sibling OS) and adjust only the following to match the Facter 4.11 key shape:

| Field | Upstream (OpenFact 5.6) | Local |
|---|---|---|
| `facterversion` | `"5.6.0"` | `"4.11.0"` |
| `implementation` | `"openvox"` | removed |
| `clientversion` | `"8.26.1"` | removed |
| `clientcert` | present | removed |
| `clientnoop` | present | removed |
| `os.support` | `{ "end": "2029-06-30" }` | removed |

All other facts are kept as-is, including `os.name = "Amazon"`, `os.family = "RedHat"`,
`os.release.major = "2023"`, `os.release.full = "2023.0"` and `networking.dhcp` (also reported by
Facter 4 on DHCP hosts). `memory.swap` stays absent; the source host had no swap, matching the
existing `redhat-10` and `oraclelinux-10` factsets.

**File:** `files/fact_sets/redhat-10-x86_64.facts` (modified)

Change `facterversion` from `"5.1.0"` to `"4.11.0"`. Its key set already matches a Facter 4.11
RedHat factset; no other changes.

**File:** `abide_dev_utils.gemspec`, `Gemfile.lock`, `.rubocop.yml`, `CLAUDE.md` (unchanged vs. `main`)

The earlier `facterdb ~> 4.5` / Ruby `>= 3.2.0` / `TargetRubyVersion: 3.2` changes on this branch are
reverted.

**File:** `spec/abide_dev_utils/ppt/facter_utils_spec.rb` (modified; currently comments only on `main`)

Add unit specs for `FactSets#find_by_fact_value_tuples` covering Amazon 2023, RedHat 10,
OracleLinux 10, Ubuntu 24.04 and Windows 2025 (asserting the expected `os.family`), plus a spec
asserting every `files/fact_sets/*.facts` file is valid JSON with a `4.x` `facterversion`.

**File:** `lib/abide_dev_utils/version.rb` (modified)

Bump version from `0.18.10` to `0.18.11`.

## Functional behavior

- `FactSets#find_by_fact_value_tuples(['os.name', 'Amazon'], ['os.release.major', '2023'])` returns
  the local AL2023 facts with `os.family = "RedHat"`, so `abide sce generate reference` and the
  coverage report can load a CIS Amazon Linux 2023 benchmark without a `BenchmarkLoadError`.
- RedHat 10 lookups through `FactSets` are unaffected (it ignores `facterversion`).
- With `FACTERDB_SEARCH_PATHS` pointed at `files/fact_sets/`, `rspec-puppet-facts` on Puppet 8
  (Facter 4.11.0) selects the local `amazon-2023`, `redhat-10` and `oraclelinux-10` factsets.
- `facterdb` stays at `~> 4.1.0` and Ruby `>= 2.7.0`; no change for `sce_windows`.

## Non-goals

- Wiring `FACTERDB_SEARCH_PATHS` in `sce_linux`'s `spec_helper.rb` so Puppet 8 RSpec covers RHEL 10,
  OL 10 and AL2023 (separate `sce_linux` ticket).
- Bumping `facterdb` or the minimum Ruby version.
- Removing the vendored `windows-2025` / `oraclelinux-10` / `redhat-10` factsets.
- `aarch64` AL2023 facts (upstream ships `x86_64` only).
- Pre-existing `main` failures: rubocop offenses not run in CI (CEM-7116) and `cli_spec.rb` exiting
  the process during `rake spec` (CEM-7117).
